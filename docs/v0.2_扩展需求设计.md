## 2. 数据采集设计
### 2.1 速度（latency）
- 来源：每次请求记录 `latency_ms = end_ts - start_ts`
- 窗口：默认 `ranking.speed_window_seconds = 3600` 可调
- 计算：P50 / P90 / P99（按模型聚合）
- Top 5 排序：P50 升序
### 2.2 智力（intelligence score）
- 来源：内置静态表 `intelligence_static`
- 字段：`pattern, score (0-100), tier (S/A/B/C), notes`
- 匹配：`model_id LIKE pattern` 取最高分
- 默认分：未匹配 → **60**
- 维护：Admin UI 可编辑
| 模型 pattern | tier | score | 备注 |
|------|------|------|------|
| claude-opus-4-* | S | 96 | 顶级推理/写作 |
| gpt-5* / o3-pro | S | 95 | 综合最强 |
| claude-sonnet-4-* | A | 88 | 强推理 |
| gpt-4.1* / gemini-2.5-pro | A | 87 | 综合强 |
| deepseek-r1* | A | 85 | 开源推理 SOTA |
| gpt-4o / claude-haiku-4* | B | 78 | 中等 |
| gemini-2.5-flash | B | 76 | 快速 |
| qwen3-235b* / llama-3.3-70b* | B | 75 | 开源中强 |
| gpt-4o-mini / gemma-3-27b* | C | 70 | 轻量 |
| qwen3-32b* / llama-3.1-8b* | C | 65 | 轻量 |
### 2.3 稳定性（stability score）
- 算法：`stab = success_rate * 100 - consecutive_fail_penalty`
  - success_rate = 窗口内 2xx / total
  - 连续 3 次失败 → −10，每多一次 −2
- 冷却中 → 直接 0
- 样本 < `min_requests_for_stability`(默认 5) → 「样本不足」，从打分池移除
### 2.4 请求日志
表 `request_logs`：
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL PK | |
| conversation_id | TEXT | |
| requested_model | TEXT | 用户传入的 model 字段 |
| routed_provider | TEXT | 最终命中的 provider |
| routed_model | TEXT | 最终命中的 model |
| status | TEXT | success / error |
| http_status | INT | |
| latency_ms | INT | |
| prompt_tokens | INT | |
| completion_tokens | INT | |
| error_type | TEXT | |
| error_msg | TEXT | |
| fallback_count | INT | |
| user_ip | TEXT | |
| api_key_id | BIGINT | |
| created_at | TIMESTAMPTZ | DEFAULT NOW() |
索引：`(routed_model, created_at DESC)`、`(conversation_id, created_at DESC)`、`(status, created_at DESC)`
记录时机：`chat_completions` 末尾统一记，**每次 fallback 尝试都记一行**，方便回放。

## 3. 综合打分公式
### 3.1 公式
```
final_score = w_speed · speed_score + w_intel · intel_score + w_stab · stab_score
```
默认权重：`w_speed=0.30, w_intel=0.50, w_stab=0.20`，三者之和 = 1.0（误差 < 0.001，否则 422）。
### 3.2 单维度归一化（0-100）
- `speed_score = max(0, 100 - clamp(P50_ms, 0, 5000) / 50)`（0ms→100，5000ms→0）
- `intel_score` = 静态表分（NULL → 60）
- `stab_score` = 稳定性分（NULL → 排除）
### 3.3 路由过滤 + 排序
1. `enabled=True` 且 `auto_enabled=True`
2. 不在 health cooling 且 `manual_cooldown_until <= now()`
3. `stab_score` 非 NULL（稳定性样本充足）
4. 计算 `final_score` 降序
5. tie-breaker：`is_free=True` 优先，再按 `priority desc`
### 3.4 锁定优先
若 `routing_pin.pinned_model_id` 非空且通过过滤 → **直接使用**，跳过打分。

## 4. 人工干预设计
| 能力 | 存储 | API |
|------|------|-----|
| 权重调整 | `routing_weights` (单行) | `PUT /admin/api/routing/weights` |
| 模型禁用/启用 | `models.is_active`（已有） | `PATCH /admin/api/models/{id}` |
| 手动冷却 | `models.manual_cooldown_until` (新字段) | `POST /admin/api/models/{id}/cooldown` |
| 锁定模型 | `routing_pin` (单行) | `PUT /admin/api/routing/pin` |
| 审计 | `admin_audit_log` | `GET /admin/api/audit` |
所有干预动作都会写入 `admin_audit_log`（actor / action / target / payload / created_at）。

## 8. 数据库迁移 SQL
```sql
-- 1) 模型手动冷却字段
ALTER TABLE models ADD COLUMN IF NOT EXISTS manual_cooldown_until TIMESTAMPTZ;
-- 2) 请求日志
CREATE TABLE IF NOT EXISTS request_logs (
    id BIGSERIAL PRIMARY KEY,
    conversation_id TEXT,
    requested_model TEXT,
    routed_provider TEXT,
    routed_model TEXT,
    status TEXT,
    http_status INT,
    latency_ms INT,
    prompt_tokens INT,
    completion_tokens INT,
    error_type TEXT,
    error_msg TEXT,
    fallback_count INT,
    user_ip TEXT,
    api_key_id BIGINT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_request_logs_model_time
    ON request_logs(routed_model, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_request_logs_conv_time
    ON request_logs(conversation_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_request_logs_status_time
    ON request_logs(status, created_at DESC);
-- 3) 智力静态表
CREATE TABLE IF NOT EXISTS intelligence_static (
    id BIGSERIAL PRIMARY KEY,
    pattern TEXT UNIQUE,
    score INT NOT NULL,
    tier TEXT NOT NULL,
    notes TEXT,
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
-- 4) 路由权重（单行）
CREATE TABLE IF NOT EXISTS routing_weights (
    id INT PRIMARY KEY DEFAULT 1 CHECK (id = 1),
    w_speed NUMERIC(4,3) NOT NULL,
    w_intel NUMERIC(4,3) NOT NULL,
    w_stab NUMERIC(4,3) NOT NULL,
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
INSERT INTO routing_weights (id, w_speed, w_intel, w_stab)
    VALUES (1, 0.30, 0.50, 0.20)
    ON CONFLICT (id) DO NOTHING;
-- 5) 锁定表（单行）
CREATE TABLE IF NOT EXISTS routing_pin (
    id INT PRIMARY KEY DEFAULT 1 CHECK (id = 1),
    pinned_model_id BIGINT REFERENCES models(id),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
INSERT INTO routing_pin (id) VALUES (1) ON CONFLICT DO NOTHING;
-- 6) 审计日志
CREATE TABLE IF NOT EXISTS admin_audit_log (
    id BIGSERIAL PRIMARY KEY,
    actor TEXT,
    action TEXT,
    target_id BIGINT,
    payload JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_audit_time ON admin_audit_log(created_at DESC);
```
种子智力数据（见 §2.2 表，SQL 在实施时一并灌入）。

## 9. 实施步骤
1. 数据库迁移（6 段 SQL）
2. 中间件 `RequestLoggingMiddleware`（chat_completions 末尾记日志，含 fallback 重试）
3. 服务层 `RankingService`（聚合 speed/intel/stab + final_score）
4. `AutoRouter` 改造：调用 `RankingService.rank_all()` 取代当前 priority 排序
5. 配置：`config.yaml` 加 `routing/ranking` 节
6. 静态智力种子灌入
7. Admin API：ranking/logs/routing/audit 共 10 个
8. Admin UI：4 个新 Tab + 干预面板
9. e2e：模拟多 provider → 看打分正确 → 调权重 → 看排序变化

## 10. 验收标准
| 项 | 标准 |
|----|------|
| 速度榜 | 5 min 内有调用即出现新数据 |
| 智力榜 | 100% 模型有分（未匹配 = 60） |
| 稳定性榜 | 样本 < 5 显示「样本不足」 |
| 综合榜 | 调权重后**下次请求即生效**（不重启） |
| 日志 | 调用完成后 1s 内可见 |
| 干预 | 禁用/冷却/锁定后 5s 内路由反映 |
| 审计 | 每次干预都留痕 |
