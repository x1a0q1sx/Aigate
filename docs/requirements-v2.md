# AiGate 需求规格说明书 v2.0
## 1. 背景与目标
### 1.1 项目背景
AiGate 是一个类 freellmapi 的 LLM API 聚合网关，已实现：
- 多服务商/密钥管理
- OpenAI 兼容 / Anthropic / GitHub Models 适配器
- Auto 智能路由（自动选举最优模型）
- 健康探测与模型排名
- 管理后台（Vue3 SPA）
### 1.2 新增需求
老板提出以下新需求：
1. **人工干预 Auto 选举**：用户可以手动调整模型的选举优先级（置顶/降权/排除）
2. **手动延迟测试**：用户可以手动触发单个模型或批量模型的延迟测试
3. **延迟可视化**：前端展示延迟大小（数值+图表），让用户直观看到各模型响应速度
### 1.3 业务目标
- 让用户对 Auto 选举有完全的控制权
- 提供透明的延迟数据，辅助用户做决策
- 提升系统可用性和用户体验
## 2. 用户与场景
### 2.1 目标用户
- 开发者：需要稳定快速的 LLM API
- 运维人员：需要监控模型健康状态
### 2.2 使用场景
| 场景 | 描述 |
|------|------|
| 场景1：手动调整优先级 | 用户发现某个免费模型延迟很高，手动把它降权，让 auto 优先选其他模型 |
| 场景2：手动延迟测试 | 用户刚添加了一个新服务商，想立刻测试所有模型的延迟，不等定时探测 |
| 场景3：延迟对比 | 用户在管理界面看到所有模型的延迟柱状图，一目了然哪个最快 |
## 3. 功能需求
### FR1：人工干预 Auto 选举
| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR1.1 | 模型增加 `priority_boost` 字段（整数，默认0），值越大优先级越高 | P0 |
| FR1.2 | 模型增加 `auto_excluded` 字段（布尔，默认false），true 时强制排除 | P0 |
| FR1.3 | 前端模型列表增加「置顶/降权/排除」操作按钮 | P0 |
| FR1.4 | Auto 路由排序时：先按 excluded 过滤 → 再按 priority_boost 降序 → 再按健康状态 → 再按延迟 | P0 |
| FR1.5 | 前端 Auto 排名页面显示 priority_boost 和 excluded 状态 | P1 |
### FR2：手动延迟测试
| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR2.1 | 新增 API `POST /admin/api/models/{model_id}/ping` 手动探测单个模型延迟 | P0 |
| FR2.2 | 新增 API `POST /admin/api/models/ping-all` 手动批量探测所有已启用模型 | P0 |
| FR2.3 | 探测结果实时返回（同步等待，不放入后台队列） | P0 |
| FR2.4 | 前端模型列表每行增加「🔍 测速」按钮 | P0 |
| FR2.5 | 前端增加「🚀 一键测速」按钮，批量测试所有模型 | P0 |
| FR2.6 | 测速过程中显示进度条/加载动画 | P1 |
### FR3：延迟可视化
| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR3.1 | 模型列表每行显示最新延迟数值（ms），颜色编码：绿<500ms / 黄<2000ms / 红>2000ms | P0 |
| FR3.2 | 健康监控页面增加延迟柱状图（用 CSS/Canvas 实现，不引入额外库） | P0 |
| FR3.3 | Auto 排名页面显示延迟数值（已实现，需确保数据准确） | P0 |
| FR3.4 | Dashboard 增加「最快模型 Top5」卡片 | P1 |
| FR3.5 | 延迟数据支持历史趋势（最近 N 次探测的延迟变化） | P2 |
## 4. 非功能需求
| 编号 | 需求 | 描述 |
|------|------|------|
| NFR1 | 性能 | 手动 ping 应在 10s 内返回结果 |
| NFR2 | 可靠性 | 单个模型 ping 失败不影响其他模型 |
| NFR3 | 可用性 | 前端操作响应时间 < 500ms |
| NFR4 | 安全 | 密钥不暴露在前端，ping 操作在后端执行 |
## 5. 数据模型变更
### 5.1 Model 表新增字段
```sql
ALTER TABLE models ADD COLUMN priority_boost INTEGER DEFAULT 0;
ALTER TABLE models ADD COLUMN auto_excluded BOOLEAN DEFAULT FALSE;
```
### 5.2 新增 API 端点
| 方法 | 路径 | 描述 |
|------|------|------|
| POST | /admin/api/models/{model_id}/ping | 手动 ping 单个模型 |
| POST | /admin/api/models/ping-all | 批量 ping 所有启用模型 |
| GET | /admin/api/models/latency-stats | 获取延迟统计（最快/最慢/平均） |
## 6. 验收标准
| 编号 | 标准 |
|------|------|
| AC1 | 用户可以在模型列表中对任意模型进行「置顶(+10)/降权(-10)/排除」操作 |
| AC2 | 被排除的模型不出现在 Auto 排名中 |
| AC3 | 置顶的模型在 Auto 排名中排在最前面（同等健康状态下） |
| AC4 | 点击「测速」按钮后 10 秒内显示延迟结果 |
| AC5 | 延迟数值用颜色编码显示 |
| AC6 | 健康监控页面有可视化延迟柱状图 |
| AC7 | 一键测速所有模型功能正常 |
## 7. 风险与假设
| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 大量模型同时 ping 可能触发服务商限流 | 中 | 批量 ping 时串行执行，间隔 0.5s |
| 前端柱状图渲染性能 | 低 | 使用纯 CSS 实现，不引入图表库 |
| 数据库迁移兼容性 | 低 | 使用 ALTER TABLE IF NOT EXISTS 模式 |
## 8. 假设
- 用户已配置至少一个服务商和密钥
- 后端 Python 环境已安装所需依赖
- 前端使用 Vue3 + Vite 构建
