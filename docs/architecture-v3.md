## 2. 核心模块详解
### 2.1 Auto 路由引擎（核心价值）
```
用户请求 model="auto"
       │
       ▼
  ┌──────────────┐
  │  获取选举池    │ ← auto_enabled=True + auto_excluded=False
  └──────┬───────┘
         ▼
  ┌──────────────┐    ┌───────────────────┐
  │ 过滤不可用    │───▶│冷却中 / 不健康 /   │
  │              │    │限流中 / 被排除     │
  └──────┬───────┘    └───────────────────┘
         ▼
  ┌──────────────┐    ┌───────────────────┐
  │ RankingService│───▶│speed(30%) + intel │
  │ 综合评分      │    │(50%) + stab(20%)  │
  └──────┬───────┘    └───────────────────┘
         ▼
  ┌──────────────┐
  │  取最高分模型  │ ← 免费模型有优先权重
  └──────┬───────┘
         ▼
  ┌──────────────┐
  │ 运行时探测    │ ← 发一个小请求(ping)，验证可用
  └──────┬───────┘
   失败◀──┴──▶成功
      │        │
      ▼        ▼
   冷却标记    返回结果
    + fallback
```
### 2.2 免费模型自动参选 + 收费模型可选参选
- **模型发现时**：调用服务商 /v1/models 获取列表
  - 匹配内置定价表识别价格
  - 价格=0 → **自动** → is_free=True, auto_enabled=True
  - 价格>0 → **默认** → is_free=False, auto_enabled=False
- **前端模型管理页**：每个收费模型有一开关「参与Auto选举」
  - 开启 → auto_enabled=True（加入选举池）
  - 关闭 → auto_enabled=False（不参与）
- **强制排除**：auto_excluded=True（即使符合条件也不参与）
### 2.3 定时评测增强
现有定时任务只做健康检查(ping)，v3 增强为「全量评测」：
```
定时触发（每10分钟，可配置）
       │
       ▼
  ┌──────────────┐
  │ 获取所有候选   │ ← auto_enabled=True + 有密钥
  └──────┬───────┘
         ▼
  ┌──────────────┐
  │ 逐个轻量评测   │ ← 发"你好"prompt，max_tokens=5
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │ 记录三项指标   │ ← 延迟ms、可用性、生成速度(tokens/s)
  └──────┬───────┘
         ▼
  ┌──────────────┐
  │ 更新Ranking   │ ← 更新模型评分缓存
  └──────────────┘
```

## 5. 技术决策
| 决策项 | 选择 | 理由 |
|--------|------|------|
| 数据库 | SQLite | 单机部署，无需外部服务 |
| ORM | SQLAlchemy Async | 与FastAPI async原生配合 |
| 定时任务 | APScheduler | 成熟稳定，异步支持好 |
| 前端框架 | Vue 3 + Vite | 已有、无需引入新依赖 |
| API兼容 | OpenAI标准 | 秒级对接所有生态工具 |
| 加密 | Fernet (cryptography) | 零配置、强加密 |
## 6. 风险与缓解
| 风险 | 缓解措施 |
|------|---------|
| 服务商API变化导致模型发现失败 | 提供手工添加/编辑模型功能 |
| 免费模型频繁限流 | RateLimiter + 冷却机制 |
| 定时评测消耗免费额度 | 极小prompt(5 tokens)，长间隔 |
| 数据库性能瓶颈 | SQLite对单机场景已足够 |
